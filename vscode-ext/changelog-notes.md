Hand-written changelog entries, for releases whose commit subjects don't read
well on the Marketplace listing.

CHANGELOG.md itself is generated at package time and not checked in; see
scripts/gen-changelog.js. By default each release's entries are its commit
subjects, filtered to vscode-ext/. Adding a section here replaces that
release's entries with whatever is written under the heading.

To write one, run `npm run changelog`, copy the section you want to improve
out of the generated CHANGELOG.md, paste it below, and edit the body. The
date in the heading is ignored -- it's always taken from the release tag --
and the body can be any Markdown, not just a bullet list.

Sections for versions that aren't tagged yet are fine: write the notes for a
release before shipping it, and they get picked up when the tag lands.

  ## 0.1.7

  - Something worth telling users about, in their words rather than ours.
