# Declarative, structured prompting to make AI agents work reproducibly

AI chat bots and coding agents have increased the speed of production of
sophisticated research artifacts like figures.
However, without proper instruction, or prompting, they can gladly generate
irreproducible outputs, much like a human can using an interactive tool.
In this tutorial we'll show how to use a `calkit.yaml` file as a sort of
declarative, structured prompt to provide the bones on which AI coding agents
can generate artifacts, while keeping the processes easy to verify
and iterate on.

If you don't have a Calkit project already, you can create one with
`calkit new project`, or if you've already been working in an AI chat session,
ask it to export a Calkit project for the work it's done so far---literally
just:

> Export a Calkit project that produces this figure.

After that, open up the project in, e.g., VS Code,
and start iterating on it with a coding agent like Claude Code,
GitHub Copilot, or Codex.

However, there is one important thing to check about the exported project.
We need to make sure the bot provides all of the primary artifacts,
not just the secondary or derived ones.
This can get a little tricky, since it may export a script,
which is a primary artifact,
but if it hard-codes data it collected from elsewhere, that data is
a derived artifact.
This can be seen in
[this Gemini Chat](https://gemini.google.com/share/8bb8909b4d06),
and the code it shared:

```python
import matplotlib.pyplot as plt
import numpy as np

# Data representing a decade of cumulative growth trends in Los Angeles County (Indexed to 2012 = 100%)
# Based on California EDD (Employment) and US Census/HUD/SCAG housing production data tracking.
years = np.array(
    [2012, 2013, 2014, 2015, 2016, 2017, 2018, 2019, 2020, 2021, 2022]
)

# Cumulative Job Growth (%)
job_growth = np.array(
    [0.0, 2.3, 4.8, 7.5, 9.8, 11.4, 13.1, 14.5, 6.2, 10.1, 13.8]
)

# Cumulative Housing Unit Growth (%)
housing_growth = np.array(
    [0.0, 0.4, 0.9, 1.5, 2.2, 3.0, 3.8, 4.6, 5.3, 6.1, 6.8]
)

plt.figure(figsize=(10, 6))
plt.plot(
    years,
    job_growth,
    label="Cumulative Job Growth (%)",
    color="#1f77b4",
    linewidth=2.5,
    marker="o",
)
plt.plot(
    years,
    housing_growth,
    label="Cumulative Housing Growth (%)",
    color="#ff7f0e",
    linewidth=2.5,
    marker="s",
)

plt.title(
    "The Jobs-Housing Mismatch in Los Angeles County\n(Cumulative Growth % Baseline: 2012)",
    fontsize=14,
    fontweight="bold",
    pad=15,
)
plt.xlabel("Year", fontsize=12)
plt.ylabel("Cumulative Growth (%)", fontsize=12)
plt.xticks(years)
plt.grid(True, linestyle="--", alpha=0.6)
plt.legend(fontsize=11, loc="upper left")

# Annotating the visual divergence point
plt.annotate(
    "COVID-19 Job Shocks",
    xy=(2020, 6.2),
    xytext=(2017, 7.5),
    arrowprops=dict(facecolor="black", shrink=0.05, width=1, headwidth=6),
    fontsize=10,
    bbox=dict(boxstyle="round,pad=0.3", fc="yellow", alpha=0.3),
)

plt.tight_layout()
plt.savefig("la_jobs_vs_housing.png", dpi=300)
print("Plot successfully created and saved as la_jobs_vs_housing.png")
```

Gemini cited a source for the data,
but it's going to take us quite a bit of work to verify the source.
Therefore, by our
[quantitative measure of reproducibility](../reproducibility.md),
it could be a bit better.

It may be even more subtle and tell you it saved a CSV file of data it
collected from various sources,
as seen in
[this chat with Claude](https://claude.ai/share/2a5b2958-4664-41d6-92f9-51ada94ccc5a).
Just like when reviewing an output generated by a human,
it's much better if they give you something runnable that produces
the output, i.e., "don't tell me, show me."
We similarly need to request that the bot creates a pipeline stage that collects
that data so we know the full provenance in a deterministic sense.

After you have a Calkit project started, you can prompt an agent by, e.g.,
declaring a new figure in `calkit.yaml`, like:

```yaml
figures:
  - path: figures/housing-units-over-time.png
    title: Housing production over time
    description: A plot of the number of housing units produced each year
      in every major US city since 1930.
    stage: plot-housing-over-time
```

Then, tell the agent to create the stage that produces that figure.
If you want it to export a derived dataset, you can declare that in the
`datasets` list.
You can tell it to create and run the stage in one go as well.
With the
[agent skills](../ai-tools.md)
installed, it will know what to do and can iterate
on your pipeline quite efficiently.

If desired, you could start filling in as much detail as you'd like, e.g.,
if you knew you wanted the plotting to be done in a Jupyter notebook:

```yaml
pipeline:
  stages:
    plot-housing-over-time:
      kind: jupyter-notebook
      notebook_path: notebooks/housing.ipynb
      description: Plots housing production over time.
      outputs:
        - figures/housing-units-over-time.png
```

Then, simply tell the agent:

> Finish the plot-housing-over-time stage and run it.

We can take this one step further and declare a question instead of an
artifact.
After all, the figures and datasets exist to answer questions,
so why not start there?
Add a question to `calkit.yaml`,
with a hypothesis if you have one:

```yaml
questions:
  - question: Has housing production in Los Angeles County kept up with
      job growth since 2012?
    hypothesis: Job growth has outpaced housing production.
```

Or, create it from the command line with:

```sh
calkit new question "Has housing production in Los Angeles County kept up with job growth since 2012?"
```

Then, with the [agent skills](../ai-tools.md) installed,
tell the agent:

> Answer the Calkit question with reproducible evidence.

Instead of simply telling us the answer,
the agent will add stages to the pipeline to collect the data and
compute the results,
run them,
and write an answer that references the outputs as evidence,
e.g.:

```yaml
questions:
  - question: Has housing production in Los Angeles County kept up with
      job growth since 2012?
    hypothesis: Job growth has outpaced housing production.
    answer: No. From 2012 to 2022, jobs grew by {jobs:.1f}% while
      housing units grew by only {housing:.1f}%.
    evidence:
      - kind: figure
        path: figures/jobs-vs-housing.png
      - kind: result
        path: results/growth.json
        values:
          jobs: cumulative_job_growth_pct
          housing: cumulative_housing_growth_pct
```

The numbers in the answer are not typed in by the agent.
They're read from `results/growth.json`,
which is produced by a pipeline stage,
so we can trace every result back through the code that computed it
to the raw data it came from.
We can check the rendered answer with:

```sh
calkit list questions
```

and verify that the evidence is current with:

```sh
calkit check questions
```

If anything upstream changes, e.g., we ask the agent to use a different
data source,
`calkit check questions` and `calkit status` will show that the answer is
out of date until the pipeline is rerun.
Since the evidence is regenerated by the pipeline,
the numbers update on their own,
but the prose may no longer be true,
so it's a good idea to have the agent review it afterwards with the
`/calkit:check-questions` skill.

Now, verifying the agent's work is a matter of checking that the
pipeline runs and that the evidence is current,
rather than taking its word for it.

However, verification only tells us that the answer is backed by
reproducible evidence,
not that the evidence actually supports the answer.
That part still requires a human to validate the logic,
and it's where LLMs are weakest.
They're very good at making arguments that sound plausible,
so a wrong answer can read just as convincingly as a right one.
Once we've verified the calculations are correct,
we need to give our full attention to critiquing the argument.
Since every piece of evidence is traceable,
we can open up the stages behind it and ask questions like:
Does the data measure what the question is asking about?
Is the calculation appropriate?
Does the answer follow from the results,
or does it claim more than they show?
For example, if the job growth numbers came from a data source that
covers a different region than the housing numbers,
the pipeline would run just fine and the evidence would be current,
but the answer would be wrong.
The agent can point us to the relevant code and data,
but we shouldn't let it make the judgment for us.

This way of working is analogous to the contrast between
[declarative](https://en.wikipedia.org/wiki/Declarative_programming) and
[imperative](https://en.wikipedia.org/wiki/Imperative_programming)
programming styles.
Instead of telling the agent all of the steps to take,
we declare the desired end result in a structured way,
and let the agent fill in the details.
Since this is happening in the context of a Calkit project,
after the agent is done creating and running the pipeline,
we can try rerunning it or check its status.
All of the steps taken, including the creation of computational environments,
are embedded inside the project so there is no ambiguity.
That is,
we don't need to trust that the AI agent did what it said it did,
just like if a human ships their outputs along with a Calkit project.

After the pipeline is built, iteration is easy.
If you don't like how a plot looks, tell the agent how to change it.
It will change the code and run the pipeline in one go.
You can take a look at the output and then check `calkit status` to be
sure the agent did what it claimed it did.
