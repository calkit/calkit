    Storage

    Calkit keeps the history of every file in your project. By default, small text files like code and LaTeX source, and figures under 1 MB, go to the project's Git repo, and everything else, e.g., datasets, larger figures, and simulation results, goes to the Calkit Hub (calkit.io).

    Those larger files can also go somewhere else, e.g., a Hugging Face bucket, Box, or an S3 bucket.

    Either way, you work with your files the same, and Calkit gets them where they need to go. Calkit uses Git and DVC under the hood, so git and dvc commands still work if you need them, but to send and get files, use calkit push and calkit pull, since they reach everywhere the project's files are stored.

    One login for everything

    You only need to log in to Calkit once on each machine, no matter where your files are stored. Calkit handles access to your storage, so there's nothing else to set up, even on shared machines like HPC clusters.

    This also means:

    • Collaborators only need access to the project. They don't need accounts with your storage provider, and you never need to share passwords or keys with them.
    • Your files go directly between your machine and your storage, without passing through calkit.io.

    Connecting your own storage

    Every account starts with Calkit Hub storage, which projects use by default. To use your own:

    1. Connect the service under connected accounts in your hub account settings.
    2. In the project's settings on the hub, select where its large files should go, create a new Hugging Face bucket, or click "Use Box" or "Use S3 bucket."

    To see where a project's files are stored and how much Calkit Hub storage it's using, run this from the project:

    calkit describe storage

    Changing a project's storage only affects files pushed after the change (see Changing where files are stored).

    Hugging Face

    A Hugging Face (HF) bucket is a simple place to keep large files, with a free allowance and low-cost storage beyond that. Usage is billed by HF and doesn't count against your Calkit plan. When part of a large file changes, only that part gets uploaded.

    To create one, go to the project's settings on the hub and click "New Hugging Face bucket," connecting your HF account if asked. Select your HF account or one of your HF organizations, and Calkit will create a bucket there named after the project and manage it for you. If that name is taken, enter a different one.

    A project's bucket has the same visibility as the project, so making a project public also makes files from its earlier versions public. To keep those private, keep the project private and publish a release instead. Calkit doesn't remove old files from a bucket, so delete them on HF if you need to.

    If you disconnect your HF account while projects are storing files with it, you'll need to choose whether to transfer those files to Calkit Hub storage or leave them on HF, where those projects can no longer reach them. Either way, your buckets stay on HF. To switch to a different HF account, disconnect the current one first.

    Connecting your HF account gives Calkit access to everything in that HF account or organization.

    Already using DVC?

    DVC has no Hugging Face remote of its own, but a DVC project can use one through Calkit:

    1. Install Calkit and log in with calkit hub login.
    2. In the project, run calkit init, which keeps your existing Git and DVC setup.
    3. Run calkit update hub to add the project to the Calkit Hub with its existing Git repo and make the hub its DVC remote. Any remote you already had stays configured.
    4. In the project's settings on the hub, click "New Hugging Face bucket."
    5. Run calkit push to send the files on this machine to the bucket. If some are only on your old remote, run dvc pull -r {old remote} first.

    From then on, use calkit push and calkit pull. A separately installed dvc can't reach the hub, so dvc push and dvc pull may not work.

    Box

    Many universities give everyone Box storage, so a project's files can live alongside the rest of your work there. Usage counts toward your Box storage, not your Calkit plan.

    To use it, go to the project's settings on the hub and click "Use Box," connecting your Box account if asked, then click it again. Files go in a folder named Calkit at the top of your Box, under the project's owner and name, and every project you send to Box shares that folder. You can move or rename it in Box, and Calkit will still find it.

    The folder stays private even if the project is public. Calkit gives people who can see the project access to its files, so they don't need Box accounts. Each file can be as large as your Box plan allows, e.g., 250 MB on a free account, and Box allows about 240 uploads a minute, so pushing thousands of small files takes a while.

    If your Box account belongs to an institution, it may need to approve Calkit first. If Box says the app has been disabled by your administrator, ask your IT department to enable it.

    Box connections lapse after 60 days without use, so Calkit keeps yours active. If it does lapse, connect Box again. Disconnecting works like it does for Hugging Face, and your files stay in Box either way.

    Connecting your Box account gives Calkit access to everything in it, but Calkit only uses the Calkit folder, and collaborators only get access to their project's folder, for an hour at a time.

    S3

    Any storage that works with S3 can hold a project's files, e.g., Amazon S3, the Open Storage Network (OSN), Cloudflare R2, Wasabi, or MinIO. Usage is billed by the provider and doesn't count against your Calkit plan.

    To use a bucket, go to the project's settings on the hub and click "Use S3 bucket." Paste in the bucket's endpoint URL, leaving it blank for AWS, and an access key ID and secret access key, then enter the bucket, e.g., s3://my-bucket or s3://my-bucket/calkit. For OSN, these are on your allocation's page in the OSN portal. Calkit saves the keys under a name, so you can use them for other projects without pasting them again, and replace or remove them under connected accounts in your hub account settings.

    Each project gets its own folder in the bucket, under the project's owner and name, so many projects can share one bucket.

    If the keys can only read the bucket, Calkit reads files from it but sends new files where they went before. This is how to share data in a bucket you don't control, e.g., with read-only keys from a data provider, without giving the keys to anyone.

    Files go directly between your machine and the bucket, using links Calkit signs with your keys. Collaborators never see the secret key.

    To show the contents of files stored with DVC on calkit.io, e.g., tables, the bucket has to allow requests from calkit.io in its CORS rules, e.g., with the AWS CLI:

    aws s3api put-bucket-cors --bucket my-bucket --cors-configuration \
  '{"CORSRules": [{"AllowedOrigins": ["https://calkit.io"], "AllowedMethods": ["GET"]}]}'

    For storage other than AWS, add --endpoint-url with its endpoint. Without the rule, pushing and pulling still work. Disconnecting keys works like it does for Hugging Face, and your files stay in the bucket either way.

    Changing where files are stored

    Only the project owner can change where its files are stored, since it uses their storage. New files go to the new storage right away, and existing files stay where they are. Calkit still finds them there, so you and your collaborators don't need to do anything.

    When deleting a project, you can choose to delete its files from Calkit Hub storage too. Calkit never deletes anything from storage you've connected, so if you no longer need a project's bucket or folder, delete it on HF, Box, or your S3 provider.

    Using your storage without Calkit

    Your files are always stored in a standard layout that DVC understands, so you're never locked in to Calkit. To get them without Calkit, download them into the project's DVC cache with the storage service's own tools and your own login.

    Public archival

    For public archival access, create a release to a service that mints DOIs for artifacts. These integrate nicely with the Calkit CLI, so clones of the project will automatically download from these services to hydrate the DVC cache and make checking them out seamless.
